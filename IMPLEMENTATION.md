# Demo implementation — 0.1

This is a native Android application built with Kotlin and Jetpack Compose. It is a first functional slice, not the complete MVP. All included athletes and timing observations are fictional. No Bluetooth permissions, hardware connection, cloud service or PC server is used at runtime.

The numbered inventory below is chronological; later entries supersede earlier pagination and dialog descriptions. Current charts show all runs with zoom, selections open in the time card, and exports use a separate format/options screen. Current build validation: 81 passing unit tests. Timer integration and field-release gates remain open.

## Try it

Install the debug APK on an Android 8.0+ device or emulator. A roughly 10-inch landscape tablet is the intended layout; narrower windows use horizontal athlete navigation. Android may ask you to allow installation from the app opening the APK.

1. Open **RaceLink Studio Demo**. Alma's latest result is selected initially.
2. Select a child and switch **Visa förbättring / Visa tider**.
3. Open **Meny → Simulator**, choose **Nästa åkare**, then press **Simulera mål**. Simulation, skier selection and demo reset live in this panel to keep the dashboard compact. Finishes and incomplete attempts go to that skier until you explicitly change or clear the selection. Browsing another child's history does not change the next skier. The currently viewed child stays on screen; **Visa nästa** opens queued finishes. The next-skier selection persists on restart and in backups, clears for a new session, and clears if that skier is removed from attendance.
4. Try **Simulera avbrutet**. Incomplete attempts remain visible and are excluded from comparisons.
5. Tap an attempt to reassign the child, mark it incomplete, add tags or write a note. Reassignment updates both children's histories and records an audit entry.
6. Open **Inställningar** to edit the team name and add/rename coaching tags. Tags use stable identities, so renamed labels update older runs.
7. Try **Markera ändring**, the light/dark switch and **Exportera CSV**. CSV excludes coaching tags/notes and labels every row as simulated.
8. Close/reopen the app. Changes persist on this device. **Återställ demo** requires confirmation and clears demo edits.
9. Open **Meny → Träningspass** to browse sessions, or **Rapporter** for each child's summary, chart and run history. Export the whole session or one child's CSV; tags and notes remain excluded from CSV.
10. Choose **Meny → Starta träningspass**. Enter a name and date, optionally location, slope/course and training type. Select participants from the reusable roster; add skiers or edit their names/bibs here. Starting archives the current session with its original skier details and saves the roster for future sessions. Archived results, tags, notes and correction history persist locally and are read-only. **Återställ demo** also deletes archived sessions.
11. In **Rapporter**, select **Alla pass · Alla åk** or one session, then **Alla åkare** or a skier. The report and CSV export follow both filters. Runs remain grouped by session, with charts per session for a selected skier; comparisons use previous completed runs from that same session. CSV includes session ID and date and omits coaching tags/notes.
12. Choose **Meny → Redigera aktuellt pass** to change session details, add/edit skiers, or change attendance. Saving keeps the session identity, recorded runs, markers and pending results and records an audit entry. Unchecked skiers remain visible with their history but do not receive new simulated finishes. Archived sessions remain unchanged.
13. Toggle quick tag chips directly on run rows, or use **Tagga senaste åket** to tag the latest finish without scrolling. Tags have two independently multi-selectable categories: **Beskriv åket** and **Fokus nästa åk**. Changes save immediately with audit history. Notes and reassignment remain in the detailed run editor. Settings supports adding, renaming and moving tags between categories. Older tags retain their IDs and selections under **Beskriv åket**, with separate default next-focus choices added once. Archived sessions retain their own tag definitions.
14. Reports show per-skier summaries for each selected session: run counts, best time, latest attempt and first-to-latest completed-run progress. **Exportera PDF** saves a paginated A4 report matching the session/skier filters and opens a page preview. Tags and notes are excluded unless their PDF checkboxes are selected. CSV continues to exclude both.
15. **Meny → Säkerhetskopiera och återställ** saves all local sessions, roster, tags, notes and audit history as a versioned JSON file. Pick a backup to validate and review session/run counts before explicitly replacing local data. Restore commits atomically with a recovery point; **Ångra senaste återställning** can restore the previous local state, also with confirmation. Invalid or unsupported backups leave the database unchanged. Backups include private notes and are limited to 16 MB. Choose an external/transferable location if you need protection against device loss; the local recovery point is not an external backup.
16. **Meny → Resultatgranskning** contains simulator actions for unknown bibs and uncertain finishes. Such events stay out of run history/reports until assigned. Choose a skier, link a duplicate to an existing run, or reject the event, then confirm. Original observations and decision history persist locally and in backup version 2 (version 1 backups still load). Exact replays are idempotent; conflicting event IDs or sequence numbers require review. Resolve all waiting events before starting another session. Archived sessions expose their original events and decisions read-only. Existing demo runs from older snapshots have no reconstructed original observations.
17. Charts show selected tags in two color-coded categories below each corresponding run position, including incomplete attempts. Each chart page fits the available width, with chart points and tag labels aligned. Reports and optional PDF tag sections retain the categories; CSV still excludes tags. Backups now use version 3 to preserve categories, while versions 1 and 2 still load.
18. Tap a chart point or its run label to edit tags/notes on the active dashboard; report/archive charts open read-only details. **Visa bara taggade åk** filters the dashboard chart and run list while keeping original run numbers and full-session comparison references. Long histories use pages of at most twelve runs with a latest-page shortcut. The compact header, side-by-side result summary and shorter chart leave more room for the full graph and its annotations.
19. **Meny → Avsluta träningspass** closes the session after confirmation without starting another one. Resolve waiting review events first. Closed sessions keep all results, tags, notes and timing evidence read-only and remain available for browsing, reports and backup. **Starta nytt träningspass** creates a fresh session and archives the closed one once. Backups use version 4 to retain closed status; versions 1–3 remain readable.
20. Portrait tablets use horizontal skier navigation to give the chart the full available width. Chart page sizes adapt to the viewport (up to twelve runs), keeping category labels readable without horizontal chart scrolling. Landscape and portrait layouts were visually checked in the tablet emulator; physical-device validation remains outstanding.
21. Reports support **Alla pass**, multiple chosen sessions, or **Datumintervall** (both endpoints inclusive), combined with one or more selected skiers or everyone. The overview, PDF and CSV use the same selection. Empty selections show no runs and disable exports; invalid dates/ranges show an error instead of silently using all sessions.
22. **Diagram i rapport/PDF** controls graphs in the on-screen report and PDF export, enabled by default. Each selected skier gets a separate time graph per selected session. PDFs use vector graphs with original run numbers, gaps for incomplete runs and blocks of at most sixteen runs for readability. Graphs are kept together across page breaks. Tag and note privacy options remain independent.
23. Swipe left across the dashboard graph to view the previous skier; swipe right to view the next skier. Navigation follows the displayed roster and stops at either end. It changes only the viewed skier, not the simulator's next-skier assignment. Taps still open run details, and vertical gestures still scroll run history.
24. Mark a run **DNF** directly in its row or select **DNF** in the editor. DNF runs remain visible but are excluded from trend baselines, comparisons, best/worst times and report-graph points. Original measured times and observations are preserved; a run with a saved time can be restored to completed. A run without a finish time cannot be restored without inventing a time. Changes persist with audit history and backups.
25. The selected skier's latest-result card includes a DNF/restore control, reachable without scrolling through run history. The dashboard run list shows newest runs first while keeping original run numbers, chronological chart order and comparison references.
26. **Tagga senaste åket** sits beside DNF on the time card and tags that displayed skier's latest run. The dashboard no longer has a separate action row for marking course changes or CSV export. CSV remains available through Reports.

## Build

On this Windows checkout, the SDK and Pixel Tablet emulator are installed under ignored `.tools/` directories. Run `powershell -ExecutionPolicy Bypass -File .\run-local.ps1` from the repository to build, boot the emulator, install the APK and open the demo. The first emulator boot can take several minutes. The launcher uses Android Studio's bundled Java when available, with the installed JDK 22 as a fallback.

Use Android Studio with JDK 17 or a compatible newer JDK, SDK platform 35 and Build Tools 35.0.0. Open the repository root. Android Studio can generate the machine-local `local.properties` file. The Gradle wrapper downloads the pinned Gradle version.

Windows: `gradlew.bat :app:testDebugUnitTest :app:assembleDebug`

macOS/Linux: `sh gradlew :app:testDebugUnitTest :app:assembleDebug`

APK: `app/build/outputs/apk/debug/app-debug.apk`.

## Boundaries

Validation on 14 October 2026: `:app:testDebugUnitTest :app:assembleDebug` succeeded; six tests passed with zero failures. No physical tablet or Android emulator was available for visual/lifecycle validation. The build reported that platform-tools was absent; that did not prevent unit tests or APK creation, but device installation through adb will require it. An additional official Gradle checksum download was not completed because automatic approval review reached a usage limit; the wrapper was retrieved from Gradle's official source repository.

- TimingAdapter isolates the simulator. Real BLE discovery/decoding, overlapping real-device correlation and background capture service are not implemented.
- The demo uses a transactional SQLite snapshot, saved off the UI thread before displaying success. It preserves local state and correction audit but is not yet the planned append-only evidence journal/Room architecture. Read failures do not silently replace saved data with seed data.
- The initial roster and session are seeded. Named sessions with date, location, course and training type, participant selection, reusable roster additions/name and bib edits, active-session editing, archiving and browsing previous sessions are implemented. Roster removal remains future work.
- On-screen per-child summaries, filtered CSV, printable PDF reports, PDF page preview and manual backup/restore with a local recovery point are implemented. Image reports, logo import and optional notification sound remain future work.
- Timing values are integer milliseconds in this simulator. This does not establish the hardware's precision or protocol.
- First device/emulator visual and lifecycle validation is still required before field use. JVM tests are not a substitute for tablet checks.
- No official timing, certified race results or production data should be stored in this prototype.

## Code structure

- `Training.kt`: pure domain model, deterministic adapter, idempotent observation ingest, comparisons and corrections.
- `TrainingStore.kt`: transactional local snapshot persistence.
- `MainActivity.kt`: lifecycle-retained state, Swedish responsive dashboard, chart, dialogs and user-directed CSV export.
- `TrainingTest.kt`: incomplete-reference handling, duplicate replay, equal legitimate times, reassignment, unknown bib rejection and deterministic simulation.
